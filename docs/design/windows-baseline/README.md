# Windows 真机 UI 基线复核（v2）

> 来源：ui-baseline-0.18.13-v2-28508c1.zip  
> 工具版本：0.18.13 候选（0.18.13.1-win@28508c1）  
> 覆盖：11 个页面/状态 × 4 尺寸 = 52 张，sha256 全部唯一。  
> 尺寸：1536×1024@100%、1229×819（125% CSS 模拟）、1024×683（150% CSS 模拟）、1440×900@100%。系统实际缩放仍 100%，125%/150% 不是真正 DPI。

## P0 / P1 实际问题

1. **顶部黄色提示条被裁切（P0）**
   - 元素：.cutter-contract-notice；
   - 文本：“发现 5 个工作区临时残留，可在缓存管理页预览并清理；项目与已完成作品不会被删除。去清理”；
   - 现象：在 1536×1024 的多个页面顶部只露出条状背景和“去清理”，提示正文被完全裁掉；1440×900 原生截图未出现该条。
   - 结论：布局/可见性问题，不是版本/权限提示；需要检查 fixed/absolute 定位、z-index、内容区顶部 padding 或截图窗口高度。

2. **悬浮剪切工具条位置错误（P1，用户实际痛点）**
   - 现象：选中文本后，“已选 4 秒 / 剪切这段 / 加入待剪清单”浮层出现在页面顶部，覆盖搜索框/搜索按钮，而不是跟随选区/鼠标；
   - 影响：遮挡搜索与筛选，按钮与选区脱节；需要改为相对选区定位 + 视口边界避让。

3. **剪切任务页顶部过于拥挤（P1）**
   - “剪切任务 / 待剪清单(1)”两个 tab 与页面标题、批量操作、隐藏按钮、统计卡挤在同一区域；
   - 表格列：状态/队列/来源/时间段/选中文案/问题/操作；标题与文案列被大量截断；“队列”对已完成任务为空显示；
   - 右侧任务详情固定窄栏，信息可读性尚可，但与主表竞争宽度。

4. **素材搜索页（P1）**
   - “候选素材”标题换行（被左侧栏/卡片头挤压）；
   - “已载入10条·命中38处·加...”被截断；
   - 右侧“最近剪切任务”列表标题被截断；
   - 悬浮工具条遮挡顶部搜索区（同上）。

5. **本地素材页（P1）**
   - 卡片缩略图大面积空白/加载中，截图时可能未加载完成；需区分“懒加载未完成”和真实加载失败；
   - 过滤按钮“当前项目/全部素材/全部/横屏/竖屏”与标题同区，层级拥挤；
   - “正在检查本地素材引用...”状态条与详情面板同时出现，信息密度高。

6. **缓存/设置页（P2）**
   - 缓存：6 个 KPI 卡中第 6 个孤立；多处“正在读取/正在扫描”占位，截图为加载中状态；右侧路径长且换行；
   - 设置：长 key-value 表 14+ 行，右侧“环境检查”孤立；顶部同样有黄色条裁切。

## 做得好的部分

- v2 已修复导航错页：每页 dataPage/heading 唯一，52 张 sha 全部不同；
- 搜索选中态浮层确实被拍到（虽然位置错误）；
- 首页项目卡/详情、任务详情、缓存明细的领域信息完整；
- 1440×900 原生尺寸下整体布局比 1536 更稳定。

## 对 mockup 的影响

- 必须保留“选区悬浮剪切”的设计，但实现要修正定位；
- 顶部提示条必须纳入 AppShell 布局，不能遮挡页面；
- 剪切任务页应减少顶部批量操作/双 tab 与主表的竞争；
- 本地素材需确认缩略图加载策略后再定网格密度；
- 125%/150% 仍需真实系统缩放验证。
