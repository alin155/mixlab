# 项目封面本地化修复规格

> 优先级：0.18.19（Batch A 之后的小修）
> 问题：首页最近项目封面加载慢；项目数据在本地，但封面 URL 指向公共源素材封面，缓存未命中时 cutter-api 要从 NAS copy，冷 SMB 下明显变慢。

## 目标

项目封面成为本地项目资产：首页打开时只读本地文件，不依赖 NAS/公共源素材。

## 方案

1. **新建项目/首次剪切时本地化封面**
   - 优先使用本次剪切生成的本地 clip 封面（export-clips/<E>/cover.jpg）；
   - 若本地 clip 封面不存在，再从源素材 cover 复制一次到本地项目目录；
   - 目录建议：workspace/projects/<project_id>/cover.jpg；
   - 记录本地路径/URL 到项目状态。

2. **项目状态**
   - 增加可选字段：cover_local_path / cover_local_url；
   - 首页渲染优先本地封面；
   - 没有本地封面时回退现有 cover_url，并显示骨架/占位。

3. **旧项目迁移**
   - 背景异步补本地封面，不阻塞首页；
   - 成功后写回项目状态；失败保留现有回退；
   - 迁移需幂等，避免重复 copy。

4. **缓存**
   - 项目封面 pin 住，不参与普通缩略图 LRU 淘汰；
   - 稳定文件名 + Cache-Control，避免重复请求；
   - 首页优先请求首屏项目封面，其他延后。

## 验收

- 新建项目后封面文件存在于本地；
- 首页刷新/冷启动只读本地封面，NAS 断开仍显示；
- 首次创建后再次打开首页，封面加载近即时；
- 旧项目在后台迁移，不阻塞页面；
- 1536/1440 截图 + 冷/热对比；
- 不改 API 契约/搜索/剪切业务规则。

## 排期

- 当前 Batch A（素材搜索/剪切任务）收尾中，不混入；
- Batch A 合并/发布后，作为 **0.18.19** 单独小修。
