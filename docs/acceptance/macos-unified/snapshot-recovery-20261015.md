# 发布快照版本一致性修复

日期：2026-10-15。Mac 候选版本 `0.2.0`，本次安装的源码提交 `a6752c6`。

## 现场与架构边界

用户在文案成片中遇到本机 `library-snapshots/391b61e6dd5ab2c882c532f145d34df8/.mixlab-library/releases/v012700/release.json` 的 ENOENT。

该目录实际只有 `v012699`，本机指针却已指向 `v012700`。共享同步器先读取 NAS 当前版本并复制对应目录，复制完成后又复制了一次 NAS 实时指针；管理端在复制期间发布新版本，即可产生此不一致。读取本机缓存状态随后返回未就绪和空版本，而智能端没有检查这个结果，继续以空版本生成目录 ID。现场目录名正是 `hash(library_root + ':')`，错误发生在登记快照之前，因此数据库中没有该坏目录的快照记录。

原架构是“管理端发布不可变版本 → 客户端复制本机 → 作品锁定本机快照”，本次保留该边界。修复应在发布本机指针前验证完整性，不通过反复删除缓存、改 NAS 指针或让作品自动换版本掩盖问题。

## 修复

1. 同步器始终写入复制前捕获的版本指针；发布前检查清单、目录版本、catalog、路径映射及搜索索引，完成后再次验证缓存就绪。
2. 智能端拒绝未就绪或空版本的同步结果。已登记快照使用前检查完整性；同名损坏目录保留到 `.invalid-*` 后重建，不再丢弃正确的新副本并复用损坏目录。
3. 失败的素材详情读取不再永久缓存被拒绝的 Promise，返回可重试的快照错误。
4. 索引接口可指定已登记的快照 ID，供更新后从同一快照恢复检查点；不能传任意文件路径。
