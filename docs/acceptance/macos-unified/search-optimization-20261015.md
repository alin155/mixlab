# 智能检索性能改造验收

日期：2026-10-15。Mac 候选 `0.2.0` / `58ff0a5`，已安装到原候选应用路径。

## 结论

作品匹配已解除“等旧全库索引完成，再为新版本建索引”的依赖。原来排队的真实 129 字、3 句作品已进入审核页，实机再次匹配约 **2.4 秒** 返回。当前为 **2 句近似待审、1 句待补充检索**，不代表三句都已匹配成功。

后台索引继续在作品锁定的 v012714 上运行，而非继续计算无关的旧版本。原 v012698 的 **719,184** 段检查点保留，抽样向量摘要未改变；观测时新任务共处理 **746,976 / 1,298,422** 段，其中 **726,854** 段复用、**20,122** 段新编码。原文案、来源、账号和已保存 Key 保留。

## 架构变化

- 交互和后台计算使用独立工作进程；停止建索引不会取消交互请求。作品检索不隐式启动或等待全库计算。
- 优先复用经过完整性校验的本机快照，恢复作品继续锁定原版本。需要最新发布时显式同步，界面说明所用版本。
- 完整语义索引未就绪时，利用已发布双字倒排召回有限候选，按需进行语义重排及相邻片段组合。完整索引就绪后，使用持久化 HNSW 近邻索引，再用原始 FP32 向量重排；按素材文件夹分区检索，避免跨范围或只过滤全库少量结果造成漏检。
- 编码缓存按原文内容、模型、分词器和编码配置寻址，跨发布复用。已验证旧模型配置和相同原文可复用旧检查点；文本或分词器变化必须失效。每快照结果文件暂保留兼容，尚未做磁盘完全去重。
- 未覆盖全库语义且没有可用结果的句子标为“待补充检索”，不会算作已证实缺句；禁止直接确认或导出。近似候选依旧需要人工试听、核对并接受，事实冲突规则保留。
- 设置页显示后台向量准备/近邻结构建立阶段、复用量和新编码量。停止用户等待不等于声称后台全库任务已经结束。

方案与边界见 [架构方案](../../architecture/smart-search-performance-plan.md)。USearch Python API 依据 [固定版本官方文档](https://github.com/unum-cloud/USearch/blob/v2.26.2/python/README.md)，依赖固定为 USearch 2.26.2 / NumKong 7.8.5。

## 性能证据

| 环境与工作量 | 耗时 | 结果与限制 |
| --- | ---: | --- |
| 隔离状态、真实 v012714 素材快照，同一 129 字/3 句文案，首次 | 9.225 秒 | 3 句近似候选，需审核 |
| 同上，再次 | 1.185 秒 | 相同数量候选；不是完整语义覆盖 |
| 实际原生应用，启动并同时迁移旧向量，首次 | 34.394 秒 | 2 句近似、1 句待补充检索 |
| 实际原生应用，再次；后台索引仍运行 | HTTP 观测 2.396 秒 | 同上；后端阶段时间 2.343 秒 |
| 10 万段真实检查点向量，HNSW 单次查询核心 | 0.525–0.934 毫秒 | 不含素材读取、模型编码和应用流程 |

隔离快照共有 **1,298,422** 段，不能把旧 v012698 的 1,292,565 段当作该版本规模。首次/再次、隔离/原生和核心/端到端指标分开报告，不用不同工作量计算夸大的加速倍数。原生首次仍有启动、存储读取及并发迁移成本，尚有继续优化空间。

10 万段数值基准包含：建图 19.301 秒、冷加载 37.278 毫秒；5 个受控扰动查询的 recall@10 均为 1.0。它只验证这组向量的检索行为，不代表所有文案召回率、全量 130 万段延迟或人类语义质量验收。

原生与隔离候选结果存在差异，不能以较快的隔离结果替代实机验收。审核页明确显示覆盖限制，待补充句保留人工检索和后续重试路径。
