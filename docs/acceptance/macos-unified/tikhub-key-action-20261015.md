# TikHub Key 测试按钮状态

日期：2026-10-15。

现有 Mac 候选 `93eb03d` 的测试按钮只在 `has_tikhub_key=true` 时启用，输入框中的未保存 Key 没有参与判断。首次填写后用户看到灰色按钮；界面没有解释需要先保存。现场还观察到建立语义索引期间全局请求繁忙，相关操作也会暂时禁用。

## 当前应用处理

通过原生界面保存了用户已填写的配置，没有读取、记录或输出 Key 内容。界面显示 TikHub、DashScope 均已保存，TikHub 测试按钮恢复可用。通过同一本机引擎的 `/smart/provider/test` 验证真实接口，返回 HTTP 200、`connected=true`。这不代表已验证 DashScope 转写质量。

用户正在建立语义索引，随后已进入博主监控添加账号。为保留进行中的任务，本轮没有重启应用；当前运行的 Mac 包仍为 `93eb03d`。现有版本使用顺序仍是“填写 → 保存配置 → 测试连接”。

## 源码修正

- 新填写的非空 Key 会启用“保存并测试”。点击后仅保存该 TikHub Key，保存成功后再测试；保存失败时不发测试请求。
- 已保存 Key 仍使用“测试连接”；空 Key 且无已保存值时禁用；请求进行中防止重复提交。
- 显示未保存/已保存的说明，不回显已有密钥。

源码验证：智能端 21/21 通过，新增组件状态测试覆盖未填、刚填、已保存及繁忙四种状态；TypeScript 类型检查和智能端 Web 构建通过。相关日志保存在本工作树 `.local-dev/macos/key-button-20261015`。此交互修正尚未封装并替换当前运行的 Mac 应用。
