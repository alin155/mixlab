# 智能匹配性能改造

目标：交互匹配不等待全库建索引，在已同步的本机快照上先得到可审核结果；后台计算跨版本复用。范围限隔离候选，不部署管理端或改 NAS 发布格式。

## 证据与边界

2026-10-15 Mac 候选 a473c64：v012714 的 3 句作品等待 v012698 的 1,292,565 段索引；现场完成约 53 万段。每次发布的文字索引约 2.08 GB，本机快照目录约 20 GB。

当前路径有四个放大器：作品自动追最新版本而复制整份索引；交互请求等待旧建索引任务；向量缓存绑定发布号；全库语义查询逐行读 SQLite 浮点向量并扫描比较。提高线程数不能修复这些依赖关系。

## 本批方案

1. 检索与建索引分开进程，交互请求不 await 后台任务，也不隐式启动全库计算。
2. 作品复用已校验的本机快照；进行中的作品恢复时沿用锁定版本。显式同步仍获取管理端最新发布；界面说明实际使用版本。
3. 文字检索继续走已有发布索引。全库语义索引未就绪时，使用已有双字倒排召回有界候选，按需计算/复用向量并重排。召回覆盖不完整时，无结果应标记“待补充检索”，不能断言缺句；近似原声仍需人工审核。
4. 向量计算缓存按模型、分词器和原文内容寻址，与发布号分离；校验后复用旧检查点，变更文本/模型不得误复用。现有每快照结果文件先保留兼容，后续再处理磁盘去重。
5. 全库就绪时使用持久化 HNSW 索引，不逐条扫描所有向量。限制素材范围时也要在相应范围内检索，不能先全库取少量结果再随意过滤。索引以临时文件生成后发布，旧检查点保留。

USearch 依赖固定版本，验证 Mac 可执行及 Windows wheel 可下载；不将 wheel 可用当作 Windows 安装验收。API 来源：[官方 Python 文档](https://github.com/unum-cloud/USearch/blob/v2.26.2/python/README.md)。

## 验收

- 持续建索引时，另一作品仍能返回候选，不等待后台任务；无语义覆盖时明确说明局限。
- 不同发布、相同原文不重复编码；修改文本、分词器或模型必须失效；旧向量只有文本和已知模型配置一致时才复用。
- 同一素材范围结果无越界；ANN 与受控暴力检索比较召回；量化冷/热查询及新版本复用耗时。
- 保留精确文字匹配、原声真实性、近似/事实冲突审核、禁止缺句直接导出。
- Mac 完成类型、回归、真实 NAS 与原生界面验证，再报告 Windows 待验收范围。

Mac 更新前备份本机数据库及向量检查点，旧包 a473c64 可回滚。真实性、召回覆盖与耗时分别报告；不把快返回当成全库质量验收完成。
