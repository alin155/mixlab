# 统一剪辑端：Mac 优先实施方案

日期：2026-10-12。起点：候选分支 `codex/unified-cutter-20261007` / `5e84bd3`。目标是完成可独立运行的 Mac 桌面候选及真实数据验收，随后复用同一业务代码完成 Windows 验收。

## 产品与架构决定

- 一个统一剪辑工作台保留原剪辑端全部核心流程：文案检索、鼠标拖选、试听、剪切/复剪、有序片段导出和合并、本机项目与文件管理。
- 普通账号使用基础功能；Pro 在此基础上增加文案成片、匹配审核、人工补句、人物取景、字幕和抖音自动创作。两种创作来源独立标记。
- 管理端负责素材预处理/发布及剪辑师审核、设备和普通/Pro 授权。管理员身份与剪辑师身份分别保留。
- 客户端读取管理端已发布的素材、转写和索引，本机承担缓存、分析、剪切、合并与输出。监控下载只用于提取参考文案。
- 保留现有 Tauri 外壳、Web UI、本机 Node 引擎和 Python 模型进程；不重写成熟剪切引擎。平台差异仅放在运行时资源、进程、目录、凭据及安装边界。
- Mac 候选自带 Node、Python、FFmpeg/FFprobe、模型与字体，启动不依赖 Homebrew、系统 Python、开发仓库或 Windows 安装。

## 数据与发布边界

生产 NAS 公共库与原账号不做初始化、重建、删除、批量发布或权限调整。真实素材验收先只读发布快照并对少量媒体执行本机输出；账号流程先在独立测试库验证，再由现有审核账号登录真实库验证。禁止拿测试账号伪装成真实 NAS 登录证据。

现有工作树、已发布安装版、NAS 服务及共享下载指针保留。候选状态与输出独立；保存切换配置前的备份。新增授权文件兼容旧账号，默认普通账号。发布/部署和向现有用户推送升级单独评审。

## 实施阶段与验收门槛

| 阶段 | 实施内容 | 通过门槛 |
| --- | --- | --- |
| A 环境与公共库 | 核对 NAS 挂载、发布指针、索引、素材数量；独立缓存和本机输出 | 明确显示真实根目录、发布版本和数量；断开连接给出真实错误；不回落到演示库 |
| B 管理端账号联调 | 独立管理端与候选共享测试库；注册、审核、登录、设备、普通/Pro、降级和禁用 | 未登录拒绝业务 API；普通账号不能调用智能 API；授权撤回阻止新任务和后台继续；原账号兼容 |
| C 真实媒体闭环 | 从 NAS 已发布口播读取文案，句内/跨句/反向拖选，剪切/复剪/合并；人工与智能创作 | MP4/SRT/来源记录真实可播放，原声对应选区；人物裁切和字幕经观看确认；记录请求与媒体耗时 |
| D Mac 桌面候选 | 平台资源适配、独立 .app、目录选择、后台菜单、明确退出、重启恢复 | 应用脱离开发环境启动，媒体及模型可用；关闭窗口继续运行；明确退出停止子进程；任务可恢复 |
| E 自动创作 | 用户在设置中配置 TikHub/DashScope；限定账号和请求量验证发现、选热度、下载、转写、创作 | 真实链路结果、限流/失败状态、重复视频去重和本机恢复；参考视频不进入素材库；未配置时明确阻塞 |
| F Windows 与交付 | 相同业务用例，增加 UNC、权限、文件锁、DPAPI、托盘、安装/升级/共存 | 业务结果一致；实机报告和版本/hash齐全；回滚路径明确；Mac 通过不替代 Windows 证据 |

执行 A/B/C 与 D 的独立工作可以交替推进；真实凭据或外部条件缺失不能阻止完成其他阶段，但相关门槛必须保持未通过状态。阶段 D 完成后才推进新的 Windows 完整验收。

## 最小必要改造

1. 按平台选择包内可执行文件，增加 Mac ARM64 候选构建与资源完整性验证；Windows 路径和打包脚本保持兼容。
2. 把素材连接状态呈现为“未配置、无法连接、已发布库已同步”，显示根目录、版本及数量，避免测试库或未挂载被误解成素材不存在。
3. 用真实 API 联调管理端账号权限，补齐仅靠 UI 隐藏不能覆盖的后台授权验证。
4. 以真实媒体与重启测试决定缺陷修复；每个改动对应复现、检查与证据，不进行无关模块重构。

## 检查与恢复

代码检查、API/媒体检查、UI截图、NAS只读证据及平台运行证据分别保存到 `docs/acceptance/macos-unified`。旧版统计断言的两项基线失败单独记录，不计为通过。外部 Key 不进入日志、报告、版本库或聊天。

退出时停止接收新任务，保存检查点并终止应用子进程；重开后把未完成任务恢复为可继续状态。清理缓存必须保护产出、活动任务、检查点和原素材。Mac 签名、公证及 Windows 正式发布留在候选验收之后安排。
