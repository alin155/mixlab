# Cutter 0.18.31：加载失败时的全局修复入口

- 背景：0.18.30 升级后仍有剪辑师停在“正在读取剪辑师工作台数据 / 本机服务未就绪”；此时侧栏反馈按钮不渲染，无法反馈或启动修复工具。
- 目标：**无论数据是否加载、本机服务是否就绪，编辑师都能在正式版里一键启动 MixLab Cutter 修复工具；严重卡住时可自动启动。**
- 优先级：P1（无法自救的加载故障）

## 1. 固定恢复入口

在桌面端增加一个不受数据/侧栏/路由影响的恢复入口：

- 位置：窗口右下角固定浮层（或顶栏右侧），始终可点；
- 文案：**无法加载？启动修复工具**
- 显示条件：
  - 桌面端；
  - 加载中（data 为空）、引擎启动中、Doctor 失败、登录/初始化页面均可显示；
  - 不依赖 `data`、侧栏、反馈按钮。
- 点击调用 Tauri 新命令 `desktop_launch_repair_tool`。

## 2. 修复工具内置到安装包

当前修复工具是独立 exe，需要从 NAS 手工发给剪辑师，不符合“正式版里直接可用”。

要求：

- 把 `apps/cutter-desktop/repair-tool/` 构建出的 `MixLab Cutter 修复工具.exe` 作为 Tauri resource 打进安装包；
- 新增 Tauri 命令 `desktop_launch_repair_tool`：
  - 解析安装目录内的修复工具路径；
  - 以独立进程启动，不等待、不阻塞 Cutter；
  - 找不到时返回明确错误，UI 显示“修复工具未安装，请联系管理员”；
- 启动后写 `desktop-host.ndjson` 事件 `repair_tool_launched`，包含 source=manual/auto。

修复工具 v1.1 已支持失败自动提交诊断到反馈收件箱，不需要额外上传逻辑。

## 3. 自动启动

在明确“卡住”而不是正常慢启动时自动启动修复工具：

- 适用条件：
  - 桌面端；
  - 配置完整；
  - 工作台数据仍为空，或本机引擎/health 长时间未就绪；
- 阈值：**45 秒**；
- 行为：
  - 显示恢复入口和倒计时/提示：“45 秒后自动启动修复工具”；
  - 超时仍卡住：自动调用一次 `desktop_launch_repair_tool`；
  - 每次应用会话最多自动启动一次，避免反复弹窗；
  - 用户可随时手动点击，手动点击不受 45 秒限制；
  - 若在阈值前加载成功，取消自动启动；
  - 首次配置/选择目录阶段不要自动启动。

## 4. 反馈兜底

因为加载失败时反馈按钮不存在，恢复入口必须至少提供：

- “启动修复工具”
- 可选：“复制诊断路径/打开日志目录”

不要求此时打开完整反馈表单；修复工具失败后会自动提交诊断包，覆盖反馈/排查需求。

## 5. 测试

1. 模拟 data 为空/引擎未就绪：恢复入口可见，点击能启动修复工具；
2. 正常加载 3 秒内完成：不自动启动；
3. 卡住 45 秒：自动启动一次；之后不重复；
4. 用户提前手动点击：不重复自动启动；
5. 修复工具缺失：UI 明确错误，不崩溃；
6. 首次配置页面不自动启动；
7. Tauri 打包后安装包中确实存在修复工具，资源路径可用；
8. 0.18.30→0.18.31 真实应用内更新 + 卡住场景真机验收。
