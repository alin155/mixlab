# 修复工具 1.3 UI/UX 重设计

- 参考稿：
  - NAS: \\192.168.1.27\MixLab\工具\MixLab Cutter 修复工具\design\repair-ui-mockup.png
  - 仓库: docs/design/mockups/cutter-repair-tool-1.3.png
- 目标：从“开发者工具”变成剪辑师敢点、看得懂的小工具；默认只暴露一个主操作。

## 1. 窗口与布局

- 窗口内容约 760 x 560，允许缩放但不要破坏布局；
- 保留 Windows 系统标题栏（不要自绘无边框窗口，避免拖动/高 DPI/无障碍问题）；
- 内容区浅灰蓝背景 #F6F8FC，白色卡片，细边框 #E4EAF3，圆角 14~16；
- 字体 Microsoft YaHei UI；标题 24~26 粗体；正文 12~13；辅助文字 11。

布局：

1. 页头：
   - 左侧标题“修复工具”+ 一句说明；
   - 右侧 v1.3.0 标签。
2. 主状态卡：
   - 状态图标（绿/蓝/橙/红）；
   - 状态标题（准备就绪/正在检查/正在修复/修复完成/需要管理员）；
   - 一行说明；
   - 三步骤进度：检查环境 → 安全修复 → 复检结果；
   - 主按钮“一键修复”；
   - 次入口“更多选项”；
   - 安全提示：失败自动提交诊断，不删除素材/项目/缓存。
3. 页脚：
   - 左：诊断日志会保存在本机；
   - 右：MixLab · Windows 桌面端。

默认不显示大段日志；放在“更多选项”里，或折叠为“查看诊断日志”。

## 2. 状态

### 准备

- 绿色对勾；
- 标题“准备就绪”；
- 主按钮“一键修复”。

### 进行中

- 蓝色状态；
- 标题随阶段变化：
  - 检查环境
  - 正在安全修复
  - 正在复检
- 主按钮禁用并显示“修复中…”；
- 步骤条高亮当前阶段；
- 不弹无关对话框。

### 成功

- 绿色；
- 标题“修复完成”；
- 说明“回到 MixLab Cutter 查看工作台是否正常”；
- 主按钮改为“完成”；
- 可选次按钮“打开 Cutter”。

### 失败/需要管理员

- 橙色/蓝色；
- 标题“自动修复未完成”；
- 显示：“已自动提交给管理员，编号 FB-...”；
- 明确“无需你手动发送”；
- 主按钮“关闭”；
- 次入口“更多选项”；
- 不要用红色大叉或技术堆栈吓用户。

## 3. 更多选项

折叠面板，仅包含：

- 回退到上一版本：显示动态检测结果，如“回退到 0.18.30”；
- 导出诊断包（备用，给管理员）；
- 打开日志目录。

不要在主界面并列“只导出诊断包/回退到 0.18.27”。

## 4. 交互与可访问性

- 主按钮可用键盘 Tab/Space 操作；
- 状态变化用文字 + 图标，不只靠颜色；
- 关键文本对比度满足可读性；
- 高 DPI 下文字不截断；
- 进行中禁止重复点击；
- 失败时不自动关闭窗口；
- 自动提交状态清楚可见，用户不需要理解 NAS/反馈包。

## 5. 验收

- 100% / 125% / 150% 缩放下布局不破；
- 默认页面无大段日志、无技术术语；
- 准备/进行中/成功/失败四态截图；
- 主界面只有“一键修复”一个主按钮；
- 更多选项默认收起；
- 1.3 逻辑（自动提交、上一版本回退）全部保留。

实现仍用 WinForms，可用自绘卡片/按钮，但不要依赖外部 UI 库。
